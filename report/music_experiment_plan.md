# 正式音乐实验待补清单

状态：2026-11-10，尚未选择正式音乐，以下是待执行计划，**不是已运行实验或听感**。主对话运行DSP实验，用户/小组选择歌曲并完成真实试听；报告对话据结果更新正文。项目初始参数可作为起点，最终采用值须有依据。

## 1. 输入与可复现记录

| 项目 | 需记录内容 | 保存位置/证据 |
| --- | --- | --- |
| 歌曲身份与来源 | 曲名、表演者/作者、版本、来源链接或取得方式、取得日期；可用的授权说明 | `audio/original/`旁的来源说明或独立manifest |
| 原文件 | 保留完整未改动文件；记录文件名、SHA-256、编码/位深、实际采样率、声道、总样本与总时长 | 原文件、results.source |
| 实际片段 | 起始样本、结束样本（exclusive）、实际起止秒；选择该段的理由 | results.source；不要仅抄CLI请求时间 |
| 软件/配置 | 固定依赖、配置快照、实际命令、输出目录；修改参数说明 | requirements-lock、config_used.json、实验日志 |
| 听前完整性 | 原曲及导出音频可打开/无损坏的实际观察 | listening_log.csv；自动读写测试不能代替此记录 |

待歌曲确定后可由主对话调整并运行（以下**示例命令未执行**）：

```sh
.venv/bin/python run.py process audio/original/your_song.wav --start 30 --duration 45 --output outputs/music/song01
```

每次参数或范围变化使用独立输出目录。默认200/1000/4000 Hz要求采样率>8000 Hz；不满足时由主对话明确更改并验证参数，不能静默重采样。本轮不自行创建假歌曲、下载音乐或填入假来源。

## 2. 必需数值与定义

| 数据 | JSON/其他依据 | 报告写法与比较注意 |
| --- | --- | --- |
| 最大绝对幅度 | original_analysis.absolute_peak | 幅度FS、带符号值、0基样本、1基声道、片段秒与原曲秒 |
| 最大带符号样本值 | signed_maximum | 与绝对峰值区分；全负输入时此最大值仍可能为负 |
| RMS / DC | rms、rms_per_channel、dc_per_channel | 原始FS单位；RMS不是LUFS，也不是听者感知响度 |
| 最强时频点 | strongest_time_frequency_bin | Hz、窗中心秒、PSD；各声道功率平均，不能说来自某个单独声道 |
| 最高显著频率 | highest_significant_frequency | −40 dB相对该信号自身全局PSD峰值；时间为该频率行最强窗；不是首次出现时刻或严格带宽 |
| 阈值敏感性 | 主对话补−30/−40/−50 dB等明确选择的分析 | 建议项目，不是题目硬性阈值。若结果不稳，解释噪声/泄漏而不挑有利阈值 |
| Welch主导频率与频段功率占比 | dominant_frequency_hz、band_power_fraction | 统计区间[0,200)、[200,4000)、[4000,Fs/2]；占比为相对量，变化不等同于其他频段绝对能量增加 |
| EQ设计与稳定性 | presets.*.settings、sos；必要时极点诊断 | 每个正式预设的参数与系数；稳定性检查针对实际参数，不说遍历了所有可能参数 |
| 处理前后峰值/RMS/频谱 | original_analysis、presets.*.raw_analysis | 共同导出衰减之前；因果相位/瞬态变化可以改变峰值位置 |
| 共同导出增益 | export.common_gain_linear/db、peak_ceiling | 包括原对比副本在内采用一个相同衰减，不逐预设归一化 |
| 实际导出峰值/越界样本 | presets.*.export.decoded_peak、raw_samples_at_or_above_full_scale | 实际WAV值用decoded_peak；新schema 2 CSV分别记录estimated_export_peak_fs和decoded_export_peak_fs。旧outputs/demo/schema 1的export_peak_fs为预计值，见INTEGRATION_REVIEW.md |

`is_formal_music_experiment`当前由流水线固定写`false`。`process`成功只说明完成一次音频计算。选曲后复制`music_review_template.json`为该曲的独立来源/实验记录，由主对话据实际材料填写曲名、版本、取得方式、原文件SHA-256、实际范围、config/results哈希和来源确认日期；与试听、截图、长时验证的状态分开。当前没有生成正式审核结果的CLI开关，待真实歌曲确定时由主对话接入审核记录支持；报告不能手改历史JSON为true。

## 4. 预设实验与讨论

从当前flat(0,0,0)、bass_boost(+6,0,0)、mid_cut(0,−6,0)、treble_boost(0,0,+6) dB开始；最终预设由实际音乐与设计目标决定。

需要讨论：原曲哪些成分占优势、为何选定频率/Q/增益、棚式频率是dB中点而非硬分频点、各响应重叠、频率网格与窗分辨能力、因果相位及片段起始零状态、阈值对最高显著频率的影响、共同衰减与感知电平的区别、噪声/过载/参数范围限制。只有音乐结果支持时才能描述其变化；不能把合成100/1000/8000 Hz三段解释成人声或乐器。

## 5. 实际试听与实时记录

`listening_log.csv`已记录两次合成示例反馈：原12秒示例调节难以辨认；换用60秒固定混合示例并提供旁路比较后，用户确认可以听出区别。新确认没有重新提供具体增益、时间、设备或音量，因此只支持基本可辨认性，不是正式音乐观察或受控听感评价。每次真实试听填：日期、匿名听者标识、输入/输出文件、片段、预设、设备、播放音量设置、是否响度匹配、观察、异常。当前共同增益策略**不做感知响度匹配**；若另做电平匹配试听，另存流程与增益，不覆盖主要实验文件。简单小组听感只能作为描述性观察，不作一般音质优越性结论。

实时层已交接合成实机/控件记录，见`real_time_evidence.md`。正式音乐阶段继续记录设备/驱动、采样率、块长、声道、状态保留、参数更新方法、输出余量、播放/暂停/停止/重置、欠载或流异常、观察时长。现实现采用阻塞写而非Python音频回调。`B/Fs`只能标为块时长；PortAudio报告延迟不能改写为已测声学端到端延迟。不得仅凭固定参数离线测试写“实时稳定且无延迟”。
